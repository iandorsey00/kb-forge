# KB Forge 架构与改进优先级

[English](architecture.md) · 简体中文

## 当前工作方式

| 流程 | 当前设计 |
| --- | --- |
| 收集与编写 | 按模板创建语言版本，或导入现有文章包。在本机浏览器工作区编辑可移植的 Markdown 和元数据。图片保存在各版本旁，通过相对路径引用。 |
| 维护与校验 | 使用已登记的文章编号和各语言版本。校验知识库中的复审日期、链接、资源和译文所依据的修订号。主动重新编号时，会在元数据中保留历史编号。 |
| 发布与查找 | Pandoc 提供文档结构。编辑器预览和 HTML 发布共用渲染器。分页 PDF 使用相同的 Markdown 解析结果，并支持可移植的主题。读者可在无需运行编辑器的情况下搜索导出站点，也可使用 PDF 文件夹。 |
| 协作与恢复 | 共享文件系统的快照支持发布预览、回滚和源文件合并。读者与编辑者使用不同目录。通过云同步目录发布时，请指定一名发布者。经校验的 ZIP 备份可解压到新目录以恢复。 |
| 安装与更新 | 使用 Python、Pandoc 和可选的 PDF 依赖。应用仅监听本机回环地址。更新通过 Git 快进合并完成。应用与知识库应存放在不同目录。 |

知识库文件遵循[文档标准](standard.zh-CN.md)。此次改进无需迁移。现有 Markdown 和链接仍可在其他兼容工具中使用。

## 第一个实施阶段

在浏览器中恢复未保存的 Markdown 和已编辑字段，保存时保留有意义的 Markdown 空白，从校验结果打开可读取的文章版本，并提示复审指向已停用内容的引用。恢复副本独立于知识库，恢复前会核对已保存版本是否发生变化。版本已变化时，可查看副本并手动复制所需内容。普通保存流程仍会在写入前检查文件是否已变化。

此阶段保留源码及分屏编辑。可视化编辑器需要能够往返转换嵌套列表、围栏、属性和未知结构，同时保留原文。浏览器本地恢复适合当前仅在本机运行的工作区，也避免将未复审的内容写入发布快照或备份。恢复副本与浏览器配置文件、本机地址和文章版本路径绑定，无法随知识库迁移。已添加的图片独立保存在知识库中。

## 后续改进顺序

1. **减少导入和分发所需操作。** 使用有代表性的可编辑源文件测试转换，从 Pandoc 已支持的格式入手。导入结果应生成可复审的草稿，并带有本地来源引用。比较单文件离线发布、现有站点 ZIP 和 PDF 文件夹在大小、搜索及可移植性方面的表现。
2. **改进维护和查找。** 继续完善确定性校验和译文复审。验证仅包含已发布内容的结构化导出，附上稳定引用及适用范围字段。将私有证据及源材料与读者输出分开。
3. **简化安装与恢复。** 根据 macOS 和 Windows 的实际安装流程评估启动器及便携式打包。在确定分发方式前，测试依赖管理和升级行为。

当测试揭示具体限制时，再评估内部标识符、OCR、AI 辅助和渲染器替换。只有在证实新标识方案能改进跨知识库合并或稳定引用后，才有理由考虑迁移。采用提取工具前，先用英文和简体中文样本评估。现有格式、协作及发布选项见[文档标准](standard.zh-CN.md)和[用户指南](../README.zh-CN.md)。
